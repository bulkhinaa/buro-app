# Клиентские экраны v0.2 — Детальное описание

> Каждый экран описан в формате: **Цель → Структура → Элементы → Состояния → Переходы → Валидация**.

---

## ЭТАП 1: ЛИД (без аутентификации)

### 1. LeadFormScreen

**Где:** лендинг + первый экран приложения для незарегистрированных.

**Цель:** Собрать минимум данных от клиента для замера + отсечь стоп-факторы на входе.

**Структура (сверху вниз):**

| Блок | Содержание |
|---|---|
| Hero | Заголовок «Ремонт под ключ за 30 дней» + краткий USP |
| Шаг 1: Об объекте | Адрес (DaData autocomplete), площадь (число, м²) |
| Шаг 2: Контакт | Имя, телефон (с маской +7), email (опц.) |
| Шаг 3: Стоп-чек | 6 чекбоксов стоп-факторов с подсказками-информерами |
| Согласие | Чекбокс «Согласен с обработкой ПД» + ссылки на политику и оферту |
| CTA | Кнопка «Оставить заявку» (disabled пока валидация не пройдена) |

**Стоп-факторы (чек-лист):**
- [ ] Планирую перепланировку (перенос стен, проёмов)
- [ ] Хочу сложные потолки (многоуровневые, с подсветкой)
- [ ] Нужны треки света / умный дом
- [ ] Нужны декоративные покрытия (Q3/Q4 — венецианская, фактурная краска)
- [ ] Хочу кухню/мебель на индивидуальный заказ
- [ ] Нужна особая плитка (широкоформат, сложная раскладка)

> Каждый чекбокс с иконкой ⓘ — при тапе показывает пояснение «Это требует индивидуального проекта и не уложится в 30 дней».

**Состояния:**
- **Пустое** (default): все поля пустые, CTA disabled
- **Заполняется**: live-валидация полей
- **Все стоп-факторы выключены + всё валидно**: CTA активна, цвет primary
- **Хотя бы один стоп-фактор включён**: CTA меняется на «Узнать больше», ведёт на StopListScreen
- **Submitting**: CTA → spinner, поля disabled
- **Success**: показать `LeadSuccessOverlay` с текстом «Заявка принята. Менеджер свяжется в течение часа»
- **Error**: toast с сообщением + retry

**Валидация:**
- Адрес: обязательно, ≥ 5 символов, по DaData
- Площадь: обязательно, число, 10-200 м² (вне диапазона → пометка «Свяжитесь индивидуально»)
- Имя: обязательно, ≥ 2 символов
- Телефон: обязательно, формат +7XXXXXXXXXX
- Согласие: обязательно

**Переходы:**
- Стоп-фактор включён → `StopListScreen` (с передачей данных формы)
- Все ОК → `LeadSuccessOverlay` → закрытие или вход в приложение через SMS-ссылку

**API:** `POST /functions/v1/submit-lead` (Edge Function)

### 2. StopListScreen

**Где:** показывается когда клиент отметил хотя бы один стоп-фактор.

**Цель:** Объяснить почему 30 дней не подходят, дать альтернативу (индивидуальный формат) или контакт.

**Структура:**

| Блок | Содержание |
|---|---|
| Иллюстрация | Дружелюбная картинка («Это особый случай») |
| Заголовок | «Похоже, у вас особенная задача» |
| Текст | «Мы делаем ремонт под ключ за 30 дней по фикс. цене. Это работает только если...» (4 условия) |
| Список ваших стоп-факторов | Чекбоксы с галочками — что именно отметил клиент |
| Альтернатива | «Если хотите ремонт под ваш индивидуальный проект — оставьте заявку и менеджер свяжется» |
| CTA 1 | «Оставить заявку на индивидуальный расчёт» |
| CTA 2 (вторичная) | «Вернуться» |

**Состояния:**
- **Default**: показ всех отмеченных стоп-факторов
- **Submitting**: при клике CTA 1
- **Success**: «Менеджер свяжется в течение дня»

**Переходы:**
- CTA 1 → отправка лида с пометкой `out_of_scope: true` → success-экран
- CTA 2 → возврат на `LeadFormScreen` (можно снять чекбоксы)

**API:** `POST /functions/v1/submit-lead` с флагом `out_of_scope=true` и списком факторов

## ЭТАП 3: ВЫБОР ПАКЕТА

### 4. AreaConfirmScreen

**Цель:** Подтвердить площадь после замера специалистом (она может отличаться от первоначальной из лида).

**Структура:**

| Блок | Содержание |
|---|---|
| Заголовок | «Подтвердите площадь после замера» |
| Карточка объекта | Адрес, дата замера, ФИО замерщика |
| Поле площади (ро) | Число из замера (заполнено системой) |
| Сравнение | «По заявке: 50 м² → по замеру: 52 м²» (если разница) |
| Информер | Если попадает в другой диапазон цены — предупреждение «Цена пакета изменилась» |
| CTA | «Подтвердить и продолжить» |

**Состояния:**
- **До замера**: показать «Замер запланирован на DD.MM в HH:MM» + `disabled` экран
- **После замера**: данные из БД, активная CTA
- **Площадь > 100 м²**: показать сообщение «Это особый случай — индивидуальный расчёт» + CTA «Связаться с менеджером»

**Переходы:**
- CTA → `TariffSelectionScreen` (передача `areaConfirmed`, `projectId`)

- Тап на «Выбрать» → запись в store + переход на `ColorSchemeScreen`

### 8. PackagePreviewScreen

**Цель:** Показать что войдёт в пакет, цену и срок. Это последняя точка где клиент может изменить выбор без юр. последствий.

**Структура:**

```
[Заголовок «Ваш пакет»]

┌─ Сводка ──────────────────────────────────────┐
│ Тариф «База» • Светлая тема                   │
│ Площадь: 52 м²                                 │
│ Срок: 30 дней (с 15 мая по 14 июня)            │
│ Цена: 720 000 ₽                                │
└────────────────────────────────────────────────┘

[Что войдёт ▾]
- Пол: Ламинат (выбор клиента)
- Двери: Дверь типовая
- Сантехника: Смеситель + Унитаз + Ванна + Душ
- Освещение: Подвесной + точечный
- Стены: Обои/краска Q2
- ...

[Что НЕ войдёт ▾]
- Кухня и техника (доп. комплектация — обсудим отдельно)
- Текстиль (Phase 2)

[Что мы делаем сами ▾]
- Закупаем все материалы
- Назначаем мастеров
- Контролируем качество (супервайзер)
- Отвечаем за срок 30 дней

[Кнопка «Готов оформить договор»]
[Ссылка «Изменить выбор»]
```

**Элементы:**
- Сводная карточка
- 3 раскрывающихся блока: Что входит / Не входит / Что мы делаем
- Цена крупно, срок крупно
- Главная CTA + вторичная «Изменить»

**Состояния:**
- **Default**: всё развёрнуто или свёрнуто (зависит от UX-решения)
- **Loading**: при подгрузке данных пакета
- **Error**: если калькуляция не сошлась

**Переходы:**
- «Готов оформить» → `ContractSummaryScreen`
- «Изменить выбор» → возврат на `TariffSelectionScreen` (state сохранён, можно перевыбрать)

**API:** `POST /projects/preview` (тариф + тема + материалы → возвращает пакет с ценой)

### 10. ContractSignScreen

**Цель:** Подтверждение подписи через SMS-код (или электронную подпись).

**Структура:**

```
[Заголовок «Подтверждение»]
[Иллюстрация конверта]

«Мы отправили код на номер +7 999 *** ** 67»

[6-значное поле ввода кода]

[Таймер «Отправить заново через 60 сек»]
[Кнопка «Подтвердить»]
```

**Состояния:**
- **Default**: поле пустое, кнопка disabled
- **Filled**: 6 цифр введены, кнопка active
- **Submitting**: spinner
- **Wrong code**: красная подсветка, «Неверный код. Осталось попыток: 2»
- **Code expired**: «Код устарел. Запросите новый»
- **Locked** (5 неверных подряд): «Слишком много попыток. Попробуйте через 15 минут»
- **Success**: переход на оплату

**Переходы:**
- Success → `PaymentScreen`
- 5 ошибок → блокировка на 15 мин

**API:**
- `POST /projects/{id}/sign-init` (отправка SMS)
- `POST /projects/{id}/sign-verify` (проверка кода)

**Элементы:**
- Описание этапа из БД
- Прогресс-бар по дням
- Чек-лист DoD (read-only для клиента, заполняет супервайзер/мастер)
- Галерея фото
- При статусе `pending_client_review` — кнопки приёмки

**Состояния:**
- **pending**: «Этап начнётся ...» (предыдущий ещё не закрыт)
- **in_progress**: основной вид
- **pending_client_review**: «Этап завершён мастером, ждём вашей приёмки» + кнопки
- **rejected**: показать причину отклонения, статус «Доделывается»
- **approved**: ✅ зелёная плашка «Этап принят DD.MM в HH:MM»

**Переходы:**
- Принять → API + возврат на Dashboard
- Отклонить → модал с textarea «Причина» + фото → API
- Назад → Dashboard

**API:**
- `GET /stages/{id}` (детали + фото)
- `POST /stages/{id}/approve` (принять)
- `POST /stages/{id}/reject` (отклонить с причиной)

## Принципы UX

1. **Без перегруза выбором**: на каждом экране 1 главное решение
2. **Прозрачность**: всегда видно «где я» (прогресс-индикатор)
3. **Никаких «может быть»**: цена и срок зафиксированы
4. **Быстрые отмены**: возврат на предыдущий экран не теряет state
5. **Успокаивающий копирайтинг**: «Мы делаем», «Не нужно ни о чём думать»
6. **Минимум полей**: не спрашиваем то, что можно получить из других источников
