# Матрица зависимостей этапов v0.2

> Источник: `Дополнительная документация/этапы_зависимость от друг друга.xlsx`


## Легенда

- ✅ — **Можно параллельно**: разные зоны и нет тех. зависимости
- ⚠️ — **Частично**: можно подготовку/часть работ, но есть жёсткие ограничения
- ❌ — **Нельзя**: прямой конфликт / зависимость / риск переделок
- — — этап сам с собой


## Ключевые правила-ограничения

| Правило | Тип | Описание |
|---------|-----|----------|
| 0.x↔Стройка (⚠️) | — | Можно вести подбор, планирование, закупки. Нельзя стартовать работы без: согласованного плана, правил, доступов/ключей и назначенного ответственного. |
| Дизайн↔Стройка (⚠️) | — | Можно параллелить, если: решения по критичным узлам (мокрые зоны, электрика/свет, перегородки) зафиксированы до начала соответствующих этапов. Иначе высокий риск переделок. |
| Демонтаж↔Финишные/отделка (❌) | — | Демонтаж пыльный и разрушает основания: финишные работы нельзя. |
| Перегородки↔Стяжка (❌) | — | Сначала перегородки/узлы примыкания, потом стяжка (иначе трещины/переделки). |
| Электрика/вент/сантехника↔Зашивка/штукатурка/потолок (❌/⚠️) | — | Скрытые работы должны быть приняты супервайзером до закрытия. Потолок черновой можно частично, если трассы уже приняты и не требуют доступа. |
| Стяжка↔Штукатурка Q1 (✅) | — | Параллельно в разных плоскостях/зонах. Обязательно контролировать влажность и защиту пола/стыков. |
| Плитка↔Q2‑Q4 (✅) | — | Можно параллельно по зонам: мокрые зоны (плитка) отдельно, сухие комнаты (Q2‑Q4) отдельно. Не мешать влажными/пыльными процессами. |
| Потолок финиш↔Стены финиш (⚠️) | — | Параллельно по комнатам при строгой защите поверхностей (плёнка/картон), иначе риск испачкать финиш. |
| Чистовая электрика/сантехника↔Финишные покрытия (⚠️) | — | Можно частично (подготовка/примерка), но финальная установка после завершения финишных покрытий в зоне. |
| Пол↔Двери (⚠️) | — | Зависит от типа дверей/коробок/порогов: обычно пол до плинтусов, двери ближе к концу. Возможна параллельность по разным помещениям. |

## Применение в коде v0.2


### Таблица `stage_dependencies`
```sql
CREATE TABLE stage_dependencies (
  from_stage_num TEXT NOT NULL,  -- '0.1'..'22'
  to_stage_num   TEXT NOT NULL,
  rel_type       TEXT NOT NULL,  -- 'parallel' | 'partial' | 'blocked'
  notes          TEXT,           -- из правил-ограничений
  PRIMARY KEY (from_stage_num, to_stage_num)
);
```

### Использование в логике приёмки
- При попытке мастера стартовать этап X:
  - Найти все этапы Y, где `to_stage_num=X` И `rel_type='blocked'`
  - Если хотя бы один Y не имеет статуса `approved` → запретить старт
- При `rel_type='partial'` — показать предупреждение из `notes` и требовать подтверждение супервайзера
- При `rel_type='parallel'` — без ограничений


### Использование в построении 30-дневного графика
Алгоритм Critical Path Method (CPM) с учётом матрицы:
1. Из 23 этапов исключить те, что не входят в выбранный тариф (например, для Базы — без 1 Дизайн-проект, без Q3/Q4)
2. Построить граф зависимостей `blocked` → последовательность
3. Сгруппировать этапы с `parallel` → параллельные ветки
4. Для `partial` — буфер +1-2 дня
5. Сумма по критическому пути = срок проекта
